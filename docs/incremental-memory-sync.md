# 个人记忆增量同步

同步仍以原始日志、图库分析结果、聊天同步记录和已授权的日历为事实来源。邮件单独读取并保留今天及前两天的内容，首页只展示今日关注项，不进入个人画像。用户同意数据处理并开启对应来源后，打开或回到应用前台时只做来源到期检查：距离该来源上次成功处理满24小时才自动执行，不按跨自然日判断。开屏自动更新不导入图库或任务记录；聊天整理文件和日历快照未变化时不构建索引，也不更新全量手动同步快照。

手动同步、任务采集后分析、独立邮件读取、独立日历分析和每日自动更新共用操作生命周期与忙状态，但各自保留进度标题、计数、失败状态和重试范围。邮件入口只连接邮箱、读取和筛选，不更新个人画像；日历分析只更新日历记忆，不顺带读取邮箱或导入图库与任务记录。新操作不会继承上一轮“已自动更新”或“自动更新已关闭”的标题。

日历页面的读取按钮将“读取系统日历＋分析记忆”作为同一个互斥操作；修改是否纳入画像等本地设置时，只分析已有快照，不把旧快照记为刚刚读取的新数据。读取或分析失败不会在页面的异常处理回调里自动再执行一次。

每个来源在执行前保存尝试时间，在成功完成后保存成功时间；手动操作也更新同一组来源状态。失败或进程中断后，本轮自动窗口内不因重新打开应用反复执行昂贵任务，下一次自动尝试间隔24小时；用户可立即手动重试。自动来源失败后保留错误界面，不能用进度弹窗消失表示成功。显式重试只处理失败来源，即使每日自动更新已关闭也可执行。部分来源状态损坏不会清空其他来源的成功记录。

任务页“一键执行”在整批采集结果保存后，另行触发一次完整的增量记忆分析，更新画像、采集分组和提醒，支持手机自控、电脑控制和通知触发。此次同步不重新读取邮件或日历；已有同步尚未结束时，等待完成后再检查新采集的数据。主动停止采集时不启动分析；任务部分失败仍同步已保存结果，同步失败保留采集文件并提示重试。图库分析结果也仍可通过汇总页手动同步。

自动更新的进度弹窗可直接关闭“每日自动更新”，也可到“我的 → 数据采集 → 每日自动更新”调整。关闭会持久保存，不影响手动同步；当前已开始的来源处理完成后，后续来源不再启动。日历未授权、邮箱未开启或缺少完整账号配置/授权码时会跳过，不弹授权窗口、不连接未配置的邮箱，也不计为同步失败。未授权日历的旧缓存保留在本机，但不再展示或发送给模型分析。

应用不再维护独立的隐私同意弹窗及本地同意记录，统一查询华为 AppGallery Kit 的隐私签署结果。系统已同意时可自动分析，未同意、协议更新需要重签或接口不可用时不假定同意。“我的 → 个人与隐私 → 隐私政策”用于查看华为托管政策；日历、麦克风等系统授权及邮件 AI 筛选、小艺记忆分享开关仍独立保留。调试包或新包名需要在华为侧具备对应的隐私托管配置，否则系统签署结果可能不可用。

日历和聊天同时需要更新时，先读取日历，再统一整理聊天及更新一次记忆索引，避免连续构建两次画像。已完成的来源会提前跳过，不重复读取邮箱授权码。

## 更新机制

- **画像**：按领域、年代、年份、季度和月份构建摘要树；大月份根据模型实际使用的精简事实投影再按事件标识哈希进行二叉分块，不再按完整事件JSON一次拆成16个小桶。新增或修改事件只更新相关分块和上层摘要。图片地址、UI标注等不进入画像指纹；模型使用的事实、日期、实体、关键词、来源及日历安排信息仍参与校验。
- **模型请求**：请求内将长路径证据ID映射为短编号，校验后恢复真实ID再保存；不存在的证据不能进入画像。中间摘要限制合并扇入和输出结论数，并检查是否收敛。截断时缩小输入，格式失败先做一次确定性的JSON校验重试；网络错误不触发拆分重试。递归深度与每个节点的请求次数均有限制，内部合并、等待与重试会回传进度。
- **事实依据**：分块允许保存单条观察，以便跨月份形成线索；最终画像继续要求多条有效证据。事件原文和检索索引独立保留，摘要不替代原始事实。日历明确标为安排，不能作为已经完成的行为。个人信息场景仍排除在自动画像之外。
- **缓存失效**：事件内容、日期、来源、日历元数据、模型 URL、模型名、处理策略或提示词变化会使相关缓存失效。单独更换 API Key 不重算历史，也不会将 API Key 保存进缓存。父摘要只使用本轮有效子摘要，不反复叠加旧画像，因此已移除的证据不会通过旧画像继续传播。
- **日志修改和删除**：已经合并的事实不能精确减去某条输入，故仅重建受影响的“月份＋来源文件”组。当前整理产物清单是权威来源；已移除来源遗留的旧产物不再被索引目录扫描重新收录。已知且实际存在的日志可通过历史快照补足目录枚举，读取失败会报错，避免误判删除。
- **事件分析**：成功的模型分类保存独立检查点；后续画像失败后重试，可直接复用这部分结果。启发式回退不会写为成功的模型检查点。
- **索引**：按变化事件修改关键词、来源、领域和场景倒排表；事件与时间分区只写受影响月份，并清理已移除的月份。实体部分沿用已有增量归并逻辑。待办等小型文档仍按当前事件生成，内容未变化时跳过写入。
- **共享读取**：一次同步及一次首页/汇总展示刷新分别共享事件快照，文件文本缓存限制在索引目录内、最多16 MiB；写入时失效，阶段结束后释放。

## 失败与恢复

模型成功的分块和事件检查点位于应用沙箱中的 `workflows/profile-consolidation/sync-cache/`。每个画像节点保留最近两个经过校验的输入版本，避免自动来源更新与手动全量同步互相覆盖缓存，文件以 `.v2.json` 结尾。模型失败或检查点损坏不会被当作成功缓存。旧版已发布、输入及模型配置未变的领域画像可直接迁移复用；原有索引、原始数据和旧检查点不删除，变化领域按需建立新分块。

索引先在私有覆盖层构建，完成后将有变化的文件暂存至 `workflows/profile-consolidation/indexes.pending-sync/`，再写入 `prepared.json`。发布是同步操作；若发布阶段进程中断，下次读取索引前校验并重放完整恢复记录。恢复文件缺失或损坏时停止读取并报告错误，不把混合版本当作正常结果。模型阶段失败不会改写已发布索引。

这些检查点只恢复数据处理，不会自动下发或重放手机 GUI 操作。用户仍需点击同步重试。

## 进度与 Debug

画像阶段显示已处理的摘要节点数、缓存复用数和模型步骤，等待、内部合并与格式重试也会更新提示；节点数量不等同于实际模型请求数。采集分组显示场景完成数量。其他阶段显示处理状态，避免把固定的99%误认为只剩1%的工作量。

开屏自动更新会显示当前阶段、实际处理计数、已处理来源数量、阶段进度条和已用秒数。连接邮箱、读取标题/正文、AI筛选、日历日期分段/详情、聊天及画像处理均回传进度；等待期间保留加载动画。进度代表处理阶段和计数，不是剩余耗时估计，也不会随计时器虚增。

打开“我的”中的 Debug 开关后，可按以下关键词定位日志；关闭时沿用统一日志开关，不额外保存诊断日志：

| 日志 | 含义 |
| --- | --- |
| `SYNC_STAGE_BEGIN` / `SYNC_STAGE_END` | 阶段名称和实际墙钟耗时 |
| `SYNC_MODEL` | 个人记忆流水线的实际模型请求数、累计请求等待毫秒、输入字符数；不是 token 用量 |
| `SYNC_PROFILE` | 摘要节点复用、更新以及调用模型的节点数；一个节点可能发出多个预算受限的请求 |
| `SYNC_ENRICH` | 待分类事件数和检查点命中数 |
| `SYNC_EVENT_DELTA` | 当前事件量和变化事件量 |
| `SYNC_INDEX_WRITE` | 实际写入和复用的文件数量 |
| `SYNC_READ_CACHE` / `PRESENTATION_READ` | 同步、展示刷新读取缓存的情况 |
| `SYNC_FINISH` | 本轮成功状态和总耗时 |

外层日历、今日邮件和个人记忆各有阶段计时。模型请求的累计等待可能包含并发等待，不能直接等同于同步总耗时。新增诊断只包含阶段、耗时和数量；画像 JSON 解析失败也不再输出原始回复。

自动更新另记录 `STARTUP_SYNC_READY`（授权和邮箱配置检查耗时）、`STARTUP_SYNC_BEGIN` 及每个来源完成时的 `elapsedMs`；邮件还记录 `MAIL_READ_DONE` 和 `MAIL_ANALYSIS_BATCH`。这些信息可区分读取邮件、AI等待与记忆处理的实际耗时，不包含邮件正文、账号或凭据。

## 首次使用与实际边界

缓存策略升级时，已发布且输入未变的领域无需重新调用模型；变化领域首次建立新分块仍可能较久。后续同样的少量新增数据主要触发相关分块的模型工作。原始日志扫描、内容哈希、部分全局 JSON 索引的序列化及展示仍会受历史总量影响，不能承诺同步时间完全独立于历史数据量。

已有几个月历史数据时，无需清空索引或重新采集。原始日志、图片和聊天记录不会被删除。更早版本快照缺少流水线标记时，首次手动同步仍会检查历史来源；模型配置或事实发生变化时才更新对应的派生结果。新索引在构建成功后发布，模型阶段失败仍保留已发布索引与成功分块；后续相同输入和配置可复用缓存。开屏自动更新不会写全量手动同步快照，因此该文件时间较旧本身不代表自动更新失败。

“最近同步”和同步提醒统一参考已持久化的成功时间：完整整理、无新增内容的成功检查，以及邮件、日历、聊天的成功检查点。尝试、失败和中断不算成功。旧版仅有完整快照时继续兼容；新增检查时间只补充到现有来源状态文件，不改历史索引。提醒文字不再笼统声称“3天未同步”。完整日志快照仍独立用于识别未整理的任务与图库记录，来源更新不会把这些记录提前视作已处理；每日来源调度也继续各自使用24小时窗口。

模拟基准在240条、2400条历史事件的同一已有月份追加1条事件，两组均只重新分析1个原始数据分块、合并4个摘要节点。这验证模型工作量的复用机制，不代表真机耗时或真实模型回答质量已经完成验证。

## 验证

`scripts/check_incremental_sync.cjs <typescript-module-path>` 执行生产业务逻辑的模拟测试：缓存、模型变更、历史编辑/删除、稀疏月份、输入预算、失败重试、发布恢复、目录枚举失败、读取缓存，以及差量索引和完整重建的随机对照。

`scripts/check_task_batch_sync.cjs <typescript-module-path>` 验证任务批量执行后的自动同步，包括两种控制方式、通知入口、停止、部分失败、并发锁、失败重试及权限变化。

这次没有执行 Hvigor 构建、签名、安装、真机同步或实际用户数据的模型请求。后续用 DevEco 安装后，可在 Debug 下比较同量新增数据的阶段耗时，并核对生成画像的语义质量。

### 索引和画像复查（2026-10-28）

- 模型成功标记统一兼容 `model` 与真实批量接口的 `model_batch`，事件检查点和重复日程都可复用。事件复制保留日历元数据，避免安排失去来源属性。
- 启用模型时，网络失败、缺失/重复事件和缺失必需字段会使本轮索引失败，不再把规则兜底冒充模型成功。已有规则兜底索引可在后续手动同步时修复；构建失败仍保留上一版已发布索引。
- 无新增时按已发布清单、必要文件、事件/画像引用和完成状态检查，合法的空结果也可复用；非空原始日志不再被当成“必须生成非空画像”的依据。
- 清单增加可选的来源模型身份、日历模型身份和画像策略指纹。局部聊天/日历更新不会把保留来源标记成已用新模型处理；旧清单继续回退到原有全局身份，无须清空历史数据。
- 同一日程的读取时间留在快照中，不再改变事件的 `last_seen_date`。内容未变化时，隔天读取不会仅因读取日期而重新生成摘要；首次升级后相关日历派生结果可能更新一次。
- 并发任务失败后停止派发排队任务，等待已启动任务结束再释放操作锁。索引来源处理复用同一调度机制，防止旧任务在重试后继续写入。
- 摘要合并只允许引用本批候选摘要实际携带的证据，不能引用同领域中未传入本次合并的其他事实。
- 进度区分“检查”“复用”和“分析变化事件”。`SYNC_ENRICH_PLAN` 在模型请求前记录待分析数和检查点命中数，最终模型调用次数继续看 `SYNC_MODEL requests`。

复查增加了真实批量响应、跨实例恢复、失败后并发排空、局部/全量模型交替、空结果、缺失产物、摘要证据边界和完整流水线二次同步等回归用例。模型响应仍为模拟数据，这些用例验证控制流与持久化，不能代替真机性能和画像语义质量评估。

### 按来源变更同步（2026-10-28）

日常同步不再依靠逐次遍历、读取并哈希全部历史日志。新的 `MemoryChangeJournal` 在任务/微信日志、聊天会话和图库结果的写入与删除之前，保存相应来源的版本。三个待处理清单位于 `workflows/profile-consolidation/source-changes/`，只保留尚未完成的来源，同一来源重复写入合并为最新版本。

- **首次接入旧数据**：建立一次来源清单，兼容已有 daily-log、整理结果和模型缓存；不清空原始记录，不强制重新调用模型生成全部画像。
- **无新增或修改**：复用日志清单及已发布索引的完成回执，不读取历史日志正文、历史整理 state 或为统计重新汇总全部事件；未变化的分组也复用统计。当天、同一索引版本的待办推荐复用已有结果，跨天重新核对时效。
- **有变化**：只读取变更日志并核对其内容。按“月份＋来源文件”整理受影响分组，保留同组其他日期的证据；索引更新只加载这些来源的整理 state，未涉及的来源从已发布事件中保留。模型/策略变化或迁移缺少必要清单时继续使用完整恢复路径。
- **图库**：首次建立导出清单，此后只读取变化日期的结果；内容相同不重写，先生成替代日志，再删除过期类别。图库清空、重新分类和失败结果仍能撤回旧输入。读取失败不会先删掉有效导出。图片引用通过 source_ref 对应的导出标记直接定位原记录，不再为每个引用扫描整个图库；标记缓存有界。
- **聊天**：无变化时跳过会话和历史提取回执读取；有变化时只检查相关会话，并只导出受影响日期/场景的日志。仍只提取近7天未处理用户文字，空提取结果仍记为已处理。
- **自动来源更新**：已完成迁移且没有待处理聊天时，不再扫描聊天整理产物；完整同步中仅日历变化时也保留已发布的任务/聊天来源，不重读它们的原始日志和整理 state。
- **失败和同步中写入**：完成回执与索引同批发布，整轮成功后才确认捕获的来源版本。新版本不会被旧同步确认清掉；成功步骤的检查点继续复用，失败或中断后可重试。
- **完整检查**：开启“我的 → Debug”，在“汇总”页面底部点击“完整检查记忆数据”。此入口扫描所有原始日志，适用于通过HDC/外部工具修改或导入文件，以及清单损坏后的恢复；普通同步依赖应用写入入口记录变更。

日志新增 `SYNC_SOURCE_CHECK mode=journal/discovery/full readFiles=...`、`SYNC_CONSOLIDATE mode=journal readFiles=... affectedGroups=...` 和 `SYNC_GALLERY ... readItems=... writtenFiles=...`，方便区分检查范围和实际写入。既有 Debug 开关仍控制日志记录。

生产逻辑模拟中，历史日志由30个增加至300个后，同一天无变化同步的历史正文/state/事件分区读取均为0，文件读取次数均为11，哈希输入字符数均为4923（模型策略等固定小输入）。这是模拟文件工作量数据，不是实机耗时或恒定复杂度承诺：来源目录清单的JSON元数据仍随来源数增长，有变化时部分事件、倒排索引、实体和画像汇总仍需要全局数据。

### 来源隔离与重复索引检查修复

- 升级变更清单时，先在本地比较原始文件的旧、新版本。发现清单不等于重新分析历史任务；只有内容变化的来源进入整理和事件分析。删除和修改仍正常撤回旧证据。
- 日历更新与历史任务各自保留来源模型标记。某个历史来源使用旧模型，不再让普通增量同步退回全部任务。新增或修改的来源按当前模型处理；如需主动重查历史模型结果，使用 Debug 下的“完整检查记忆数据”。
- 开屏自动更新已成功发布的日历索引，可以被后续手动同步接续使用，不再因为手动快照的版本较旧重复生成。完成记录核对当前模型、日历输入、日程时间边界及必要索引文件；真实变化不会被跳过。
- 完成记录表示这一代数据已成功发布；保留来源的模型身份仍写在各来源中，并不表示全部历史内容都被当前模型重新分析过。
- 诊断增加 `SYNC_REFRESH_PLAN`（变化文件数、日历变化、是否复用已发布版本）、`SYNC_INDEX_PLAN`（完整或变化来源范围及保留数量）、`SYNC_SOURCE_FAILED`（失败来源）。模型超时提示区分事件、画像、分组等阶段，已有事件和画像检查点继续保留。

新增回归覆盖77个历史任务的升级场景、混合历史模型、自动更新后手动同步、真实模型客户端的模拟超时与重试、升级时的真实任务修改、失败来源定位及日程跨越结束时间。仅日历变化不会读取历史任务的整理文件；邮件和日历的实际网络请求仍可能耗时，测试没有调用真实服务。

### 真机旧索引迁移补充

旧版成功快照可能没有 `catalog_schema`，也没有新版 `completion.json`。恢复判断现在比较原始文件清单中的路径、内容摘要及条目数；日历指纹或清单格式改变不代表原始任务改变。相同月份/来源的整理文件存在性只检查一次。即便需要检查整理阶段，空的来源变化集合也会继续作为明确范围传递，避免落入默认全量索引入口。

在一台保留长期数据的设备上，只读核对809个原始文件，变化数为0；旧清单有77个整理来源、2572条已发布事件，其中188条保留旧版规则回退标记。普通无变化同步不会为了补做这些历史回退事件而请求模型，也不会导入失败后留在整理目录中的未发布修改。旧回退标记继续保留；显式完整检查仍可重新分析历史结果。

并发检查时，已完成的缓存来源不会再覆盖其他来源正在等待模型的进度。真正有变化事件需要分析时，界面显示“正在等待微信的模型分析”等状态及待处理事件数，避免长时间只显示“检查索引76/77”。

### 流式分析与事件级失败隔离

记忆流水线的模型请求改为流式接收，单次读取超时为2分钟。同步弹窗显示每批请求的首包等待、输出字数、最近输出间隔和校验状态；开启 Debug 后可以展开查看有界的末尾输出片段与疑似重复输出提示。服务只返回普通 JSON 时仍兼容，但会提示未提供实时流式数据。

事件批次中，完整且通过字段校验的事件立即保存检查点；其余事件若超时或输出异常，单独保存失败标记，继续处理成功事件。后续同步不自动重试同一语义输入与模型配置的失败事件；输入或模型配置发生变化后可重新分析。失败事件不作为已分析事实进入索引，原始记录保留。登录、配置、限流、取消及检查点写入错误仍会正常报错，不作为单条事件失败静默跳过。完成回执和界面记录跳过数量。

记忆同步各阶段（事实提取、语义去重、索引事件、画像、实体整理、采集分组和提醒分析）检测到连续重复片段时，立即销毁当前网络请求，不再等满2分钟，也不对这次循环输出做格式重试。正文与思考输出分别检测，界面提示和自动中断共用同一检测结果，关闭 Debug 时同样生效，且不记录原始输出日志。索引事件中已完整解析的结果先保存，该批未完成事件记录 `repeated_output` 失败标记，其他批次继续执行。事实提取和去重仍使用原有规则回退继续整理；其他阶段保留各自的错误处理和已完成缓存，不把未完成的模型回复当作成功结果。界面显示“重复输出已中断”；普通聊天网络客户端不受影响。检测属于重复模式启发式，不能作为模型死循环的严格证明。

同步结束提示的失败数量只统计本轮实际遇到并跳过的事件（含本轮新失败），按事件去重。未涉及的历史来源与直接复用的来源不计入；无变化、直接跳过整轮同步时计数为0。完成回执仍保存历史失败总数供诊断，两种统计不混用。
