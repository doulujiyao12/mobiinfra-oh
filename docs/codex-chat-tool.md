# 聊天中委托 Codex

在聊天中提出编程、制作 PPT、Word、Excel、PDF 等需求，手机 Agent 可以调用 `run_codex_task`，把适合电脑执行的部分交给已配对的 Codex 连接器。

## 使用流程

1. 在 App 的 **Codex** 页配对并保存电脑 / 服务器，电脑连接器保持运行，并配置可用工作目录。
2. 回到支持工具调用的**云端聊天**，例如输入「帮我制作一份介绍端侧智能体的 PPT，并交付文件」。是否委托由手机 Agent 判断。
3. 首次委托时选择电脑和工作目录，确认任务以及本条消息要发送的图片。默认新建独立 Codex 会话，权限固定为**工作目录内修改、请求批准**。
4. 原聊天出现委托卡片，显示执行进度及审批。涉及额外权限或需要回答的问题，仍由用户在卡片确认。
5. Codex 完成后，手机自动接收最终交付文件。卡片可预览图片、打开支持的文档，或通过系统文件选择器另存为。手机 Agent 收到文本和文件清单，继续判断目标是否完成；必要时继续原委托修改成品。

每次独立委托新建远端会话；修改已有成品时，Agent 通过本聊天**最新一轮返回的 `run_id`** 继续原会话。每一轮仍有独立结果卡片，文件跟随所属轮次显示。

设备和文件夹采用独立的单选列表弹窗，选中后点击“继续”。选项标题字号统一；长名称或地址可左右滑动，选项较多时可上下滚动列表。点击取消、系统返回或弹窗外部都会取消本次选择。

## 结果与恢复

- 工具返回执行状态、委托编号、电脑名称、结果摘要、文件清单和手机实际接收情况。文件二进制和连接凭据不会放进模型的工具结果。
- 手机保存恢复所需的委托状态、最终答复和交付清单，不持久保存远端的中间推理或命令输出；调试日志仍沿用 App 现有开关。
- 图片展示、文件打开和导出复用现有 Codex 文件组件；下载复用分块、大小限制、SHA256 校验和原子保存。只接收电脑端根据最终答复链接收集的成品，不扫描工作目录中的临时产物。
- 文件仍保存在 App 沙箱的 `codex/sessions/<电脑地址摘要>/<Codex会话编号>/artifacts/` 下；聊天只引用它们，不重复拷贝。
- 停止聊天或委托卡片中的“停止”，会尝试中断对应远端任务。只有远端明确返回中断才显示“已停止”；响应不明时保留“待同步”。
- 连接中断后，**不会自动重复下发**。使用原卡片“同步结果”查询同一个请求并接收文件。重启后也可恢复；删除配对、移除电脑工作目录或其他端修改了同一会话时，会明确提示。
- 恢复同步只查询原任务；不会自动恢复已结束的聊天推理。同步后可在原聊天继续提问，例如「检查刚才的文件是否完成需求」，Agent 会读取最新结果。
- 单次前台等待最长 30 分钟，超时保留原任务并允许同步，不声称远端已停止。系统可能挂起后台 App；返回后可同步。

## 实现边界

当前接入 `ChatReactAgent` 的工具调用流程，保留纯本地原生模型推理以及旧 PC Server 聊天模式的原有行为；这两种模式本轮未新增 Codex 工具执行。

当前消息中由用户附加的图片可以发送给所选电脑（最多 6 张、每张 8 MB）。Agent 无法通过工具参数指定任意手机文件路径、其他聊天或桌面历史会话，也不能提升权限。其他聊天附件类型沿用已有聊天能力，未新增任意文件上传入口。

手机 Agent 根据 Codex 的文本与文件清单做下一步判断；不会自动解析整个 Office/PDF 文件或把图片二进制注入模型上下文。需要检查具体成品内容时，可继续委托同一 Codex 会话。

本功能复用现有连接器的 `/v1/info`、任务、审批和文件接口，不修改 Codex 内核，也无需新增桌面协议或重新打包电脑端。连接器需支持权限设置及文件回传；旧版本会提示更新。

## 静态和模拟验证

`scripts/check_codex_chat_tool.cjs` 在 Node 中加载生产 ArkTS 业务逻辑，以模拟连接器验证会话隔离、续改范围、权限、下发超时、断线恢复、审批、停止、图片上传路径、按轮交付和工具 JSON 长度；同时验证工具结果回到 ReAct 后继续推理。

本轮未执行 DevEco/Hvigor 编译、安装或真机操作。仍需在 DevEco 编译后，实际检查原聊天交付 PPT/文档/图片、审批、停止及断网恢复的完整体验。
