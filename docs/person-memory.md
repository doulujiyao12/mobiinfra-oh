# 人物资料与记忆检索

汇总页的“个人信息”提供本人、父亲、母亲、伴侣四个入口。入口由 `PersonMemory.PERSON_SLOTS` 定义；资料字段由 `PERSON_FIELDS` 定义，编辑、校验和查询共用这些定义。

## 数据和归属

- 每个人有稳定主体 ID，例如 `person:self`、`person:father`。姓名或微信昵称改变不会改变 ID；同名不会合并人物。
- 当前资料保存在 App 沙箱 `people-memory/subjects.json`。一份原子文档同时是可编辑资料和小型结构化索引源，没有需要另行同步的副本。
- 每个非空字段投影为一个稳定事实 ID，例如 `person-fact:person:father:company`；`subjects` 明确姓名、关系和主体 ID，`fact_source` 标记字段及 `user_confirmed` 来源。
- 出生日期是字段值。事实日期表示资料最后确认的本地日期，不把出生年份当成采集年份。
- 保存有逐人物 revision 检查，避免旧编辑页覆盖新保存；原子写入失败不会先宣称保存成功。清空字段会立即移除对应的当前事实。清空手填资料不删除独立的历史采集记录。

## 与现有索引的关系

`IndexService.query` 和 `queryBounded` 统一返回历史事件与当前人物事实；关键词、领域、实体、时间、场景和人物过滤对当前事实生效。用户确认的当前资料优先返回，结果仍受统一数量限制。

`query_events`、`search_memory` 均支持可选的 `subject_ids`，例如：

```json
{"keywords":["工作单位"],"subject_ids":["person:father"]}
```

工具结果保留人物和来源信息；语义检索、任务补充继续使用原有同一套检索入口。不把完整住址、电话等手填资料自动拼入每一轮聊天的背景提示，只返回本次查询匹配的资料。

历史事件的 `subjects` 为可选元数据。没有明确人物标记的历史记录不会被默认标成本人，也不会仅因同名就绑定某个家人；它们仍可在不限定主体时正常查询。本次不进行历史重标记或模型重分析。

## 与同步、画像的边界

当前事实存储独立于历史索引提交目录，后台同步的索引事务不会覆盖用户刚保存的资料。编辑只处理四份人物资料，不扫描、哈希、改写历史月份，也不调用模型。

历史事件分组、个人画像摘要继续查询历史事件（`IndexService.query(options, false)` / `loadEvents`）。手填字段不被重复转成采集事件，不触发旧摘要重建，家人的资料不进入本人的 AI 画像。当前事实层本身就是确定性的人物档案，Agent 读取时应优先于历史推断。

汇总中保留“从记录中整理”的原有个人信息，和可编辑的四个人物档案分别展示。默认不把历史推断自动填入手工档案，避免未经确认的人物归属。

## 验证

人物存储和索引的聚焦检查：

```powershell
$env:SYNC_TEST_FILTER = 'people:'
node scripts/check_incremental_sync.cjs <DevEco TypeScript 模块路径>
Remove-Item Env:SYNC_TEST_FILTER
```

检查覆盖原子保存、并发编辑、字段替换/清空、同名人物隔离、主体过滤、已有事件保留、无需重建历史、场景 ID 和页面路由。真实布局、键盘避让和路由返回仍需在编译后的手机 App 验证。
