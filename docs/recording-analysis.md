# 录音分析

入口：**汇总 → 录音分析**。录音与结果单独保存在本机，不参与个人画像、聊天记忆、提醒、任务采集或每日自动同步。

## 使用

1. 主页保留搜索、声音来源、连接手表和所有录音。底部采用紧凑的单行悬浮胶囊，横向排列“导入”和“录音”，使用随深浅模式变化的半透明背景、系统背景模糊、细边框与轻阴影。点击录音开始，录制中切换为“停止”并保存；也支持其他应用分享/打开 WAV。列表可在胶囊后方滚动，末尾预留避让空间，最后一条记录仍可完整滑出。录音库和详情分别展示，返回详情上一级即可回到列表。
2. “更多”直接打开带返回按钮的全屏录音设置界面，不再弹出操作菜单。在“转写模型”选择“系统模型”或“SenseVoice”，新默认使用系统模型。系统使用鸿蒙离线普通话识别，无需下载 SenseVoice；SenseVoice 支持多语种，在设置中的“离线语音模型”准备约 270 MB 模型，默认使用 [ModelScope 镜像](https://modelscope.cn/models/fengerhu1/recording-analysis-models)，保留自定义目录与离线导入。转写、人声检测与声纹计算在手机完成，音频和声纹不发送给 Planner。
3. 默认开启“边录边转写”，摘要方式默认云端，均可在录音设置中调整；已有保存的个人选择保留。系统模型会显示正在识别的句子，结束后保存最终文字并沿用现有摘要流程；已有 WAV 和手表录音也可使用系统转写。系统模型固定普通话，SenseVoice 仍可选择自动识别、普通话、英语、日语、韩语、粤语。开启说话人区分后使用 SenseVoice，选择系统模型会关闭说话人区分。

4. 详情顶部显示录音标题、日期和紧凑播放器，下方用“转写文本 / AI 摘要”胶囊切换。正文采用 17 vp、27 vp 行高，直接呈现连续段落；说话人标签、时间和片段回听收在同一行。转写和摘要配置统一放在录音设置界面。录音列表左滑可重命名或删除，删除需确认；详情的“更多”设置界面还保留单条录音操作。“说话人”或设置中的“说话人与声纹”可修改称呼、筛选对话或比较声纹。编辑和结果自动保存。
5. 默认开启转写后生成摘要，可在设置关闭。在“更多 → 录音设置”的“摘要方式”选择本地或云端，选择保存在本机，默认云端。只处理转写文字，要点、结论、行动和待确认事项保存到本条录音。用户手动命名后保留该名称；旧记录只对可识别的自动名称应用摘要标题，避免覆盖历史自定义名称。
   - 云端沿用现有 Planner 配置和账号访问控制，长转写按有界文本块整理并递归合并，不静默截掉末尾。
   - 本地复用“我的 → 模型与智能体”中已下载的大模型及所选 CPU/NPU 模式，不使用离线语音识别模型生成摘要；未下载时引导到本地大模型下载处，不回退至云端。按约 1000 词独立整理（中文按字、英文按词近似计数，另设 5000 字符保护，超长英文词或 URL 也会拆开），每段保留时间范围、摘要及待办；分段切入同一说话人的转写时补充该说话人标记。整体标题取第一段摘要中的标题，不再做一次全量合并请求。
   - 本地摘要每段的“值得记下”“已达成的结论”“接下来要做”“有待确认”各最多三条，去重后保留模型按重要程度排列的前三条，保存前由代码强制执行。提示词要求每条最多40字、概述最多80字、总内容尽量短于原转写，没有依据的栏目保持空数组。旧本地摘要同样按每栏三条展示，保留其已保存原始条目和完成进度，不触发重新生成；云端仍按原上限处理。
   - 每完成一段即原子保存。失败或取消后保留转写、已完成摘要及原有成功结果；“继续生成本地摘要”从未完成处继续。转写、说话人称呼、模型身份或分段规则变化时重新分段；“更多 → 重新生成摘要”主动重做。详情按段阅读摘要与待办，较多段落分批展开。
   - 本地摘要通过独立文本接口处理，每段重置临时推理上下文并恢复模型配置，不追加到聊天历史；独立取消信号不会取消聊天请求。本地摘要占用模型期间禁止修改模型文件。新接口使用动态输入缓冲，不受原有单轮接口 4096 字节缓冲影响；必须重新编译含新 `libentry.so` 的 App 才可使用。模型生成能力和 CPU/NPU 性能仍需真机验证。
   - 两种摘要共用空值 JSON 结构，字段说明放在结构之外，避免模型把填写说明当成结果。共用模型响应解析器，兼容完整 JSON 前后的说明、代码块、思考段、结束标记，以及单引号、中文引号、尾逗号、注释、字符串内换行、完整值之间缺逗号和一层 JSON 字符串编码。也兼容可选列表缺失/null、常见字段别名、单层结果包装和只有 text/content/description 的列表对象；包含额外结构化信息或冲突文本的对象仍拒绝，避免静默丢字段。标题缺失或照抄标题说明时取真实摘要正文开头；列表去除重复条目。读取旧录音时也做标题和列表整理，保留已完成分段、生成时间、原文和手动名称，读取本身不改写文件、不触发模型。截断、多个冲突结果或缺失正文仍不补造。解析失败仅在 Debug 开启时记录原因和有界输出。
   - 本地摘要格式失败时，只对失败段自动简短重试一次，不重新生成成功段、不回退云端。最新失败响应（最多32768字符，超出时标记截断）随本地摘要草稿保存。再次继续时先尝试解析这一响应，能安全恢复则直接提交，无需再次推理；真正缺失的输出仍需重试生成。取消、模型调用错误和存储错误不触发格式重试。提示词要求简短、去重，不把讨论或愿望当成决定。
6. “更多 → 删除录音”确认后删除该条音频、转写、摘要和声纹，不删除通用模型，也不远程删除手表文件。

### 日期浏览与录音卡片

- “所有录音”使用七天日期条，可左右滑动切换周，点击月份展开整月日历；左右箭头切换月份。有录音的日期显示圆点，点击日期查看当天录音，“全部日期”返回完整列表。按录音创建时的本地日期筛选，不删除或重写录音。
- 列表采用时间线与圆角卡片，显示时间、时长、转写状态、标题及两行摘要；没有摘要时显示已有转写。卡片按内容自然收缩，时间线不参与剩余高度分配，左滑操作使用独立的紧凑高度，避免单条录音撑满屏幕。不添加分类。
- 日期筛选只影响浏览。输入问题后搜索整个录音库，时间范围由搜索问题决定，取消搜索后恢复之前的日期选择。

### 独立录音搜索

- 录音列表顶部提供搜索栏，新默认开启“AI 搜索”，开关统一放在“更多 → 录音设置”，保留已有保存的选择。关闭后，普通搜索将整段输入作为一个关键词，在标题、已有摘要、说话人名称和全部已转写文字中做字面匹配（英文忽略大小写），不会调用模型。
- 开启“AI 搜索”后点击搜索，固定使用“云端模型”的 Planner URL、模型名和 API Key；聊天页是否选本地模型、摘要是否选本地均不影响搜索。未登录时沿用 AI 登录检查。
- 云端先根据设备本地日期、星期和自然周/月边界解析录音创建日期范围与候选词；手机在范围内匹配现有文字。没有命中时，每批最多 12 条标题、已有摘要和说话人名称供云端判断相关性；未转写录音只能依据这些既有信息匹配，不会为了搜索重新转写音频。
- 命中的录音以列表返回，点开可查看和播放。回答仅使用前 6 条相关录音的摘要与有界转写片段，以编号对应下方条目；结果较多时会说明回答覆盖范围。AI 格式错误最多纠正一次；回答失败保留已找到的条目，部分标题/摘要匹配失败会明确提示。
- 输入变化、切换模式、离开页面或点击停止都会取消本次搜索，晚到的旧响应不能覆盖新问题。只在用户点击 AI 搜索时发送必要文字；不上传原音频或声纹向量，不读取/修改个人画像、记忆索引、日历和邮件，也不将录音写入这些系统。

### 系统转写与长录音

- 通过 `CoreSpeechKit.speechRecognizer` 的离线 long 模式、音频流输入和 partial result 回调实现。复用现有采集器和 WAV，识别引擎不再单独开启麦克风，因此兼容环境音、已获授权的系统音及混合音。
- 音频按 40 ms/1280 字节送入系统。为兼容 `writeAudio` 文档仍标注的 60 秒限制，连续录音采用最长 55 秒识别会话，45 秒后遇静音可提前衔接；硬边界重读 0.8 秒，仅在该人工重叠处裁掉短重复前缀。识别会话切换时继续录音，待处理音频留在原 WAV 中，不创建第二份录音，不一次加载整段音频。
- 支持产品现有的最长 12 小时录音，通过多个有界会话处理。录音中间结果实时显示，已确认会话追加保存到 `system-transcript.jsonl`；停止时等待尾句确认。错误或暂停保留录音与已有文字，文件转写可恢复已完成会话；重新转写成功前保留旧成功结果。
- 系统接口没有词级时间戳和说话人标识；界面播放定位采用该会话的近似时间范围。已有文件也按系统要求的音频节奏输入，处理耗时可能接近录音时长；此限制不影响现场边录边转写。
- 麦克风、内录授权和后台录音沿用现有流程，不新增 ACL 权限；识别服务是否能长期在后台运行、连续会话稳定性及准确率仍须实机验证。系统识别失败会明确显示错误，不自动切到云端或悄悄改为只录音。

参考：[华为语音识别开发指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/speechrecognizer-guide/)、[语音识别 API](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/hms-ai-speechrecognizer/)。

### 离线模型的分析与继续转写

音频以最长五分钟为一块，边界额外读取一秒上下文。录音详情的“区分说话人”默认关闭，选择保存在本机；关闭时只做人声检测和 SenseVoice 转写，不加载说话人分段/声纹模型、不把所有声音认作同一个人。开启前弹窗说明准确率和耗时影响，确认后才保存开启状态；已有结果不会立即改变，需要重新转写。边录边转写保持快速模式，不因这个文件转写开关自动重跑整条录音。

开启区分时，每块先检测人声，再划分说话人、匹配跨块声纹，最后用 SenseVoice 逐片段转写。说话人分析前保留每段人声前后半秒上下文，将较长静音压缩为半秒间隔；分析结果映射回原始录音时间，保留重叠发言，转写仍使用原始音频。连续讲话较多时，可减少的计算量较小，不能承诺固定加速倍数。

推理线程数按当前 Worker 的可用 CPU 分配：原生接口读取在线 CPU 数与调度亲和掩码的交集，大于两个可用 CPU 时预留一个，最多四线程；实时转写仍最多两个线程以保留采集资源。模型依次执行，不并行启动多个音频块。此策略是有界默认值，并非实测最优值；不同 CPU 大小核、负载和温度下需比较实际耗时。没有改变设备调度亲和性、申请后台保活或替换模型。

带说话人区分的转写断点保存在每条录音目录的 `audio.wav.analysis.json` 和 `audio.wav.analysis-current.json`，快速模式独立使用 `audio.wav.transcription.json` 和 `audio.wav.transcription-current.json`。切换模式保留另一种模式的未完成断点，恢复时只读取当前模式。完成的前缀每五分钟原子保存一次，当前块在所需阶段完成后和每个转写片段结束后原子保存；写入先 fsync 临时文件再 rename。当前块文件有界，逐片段保存不反复改写整场会议的转写。断点包含输入文件身份、模型目录、语言、处理版本、说话人映射和进度，避免恢复到不同输入上。历史六线程的计时数据仍兼容。

停止、离开页面或熄屏进入后台时暂停分析，回到页面点击“继续转写”。完成的阶段会复用；仍在执行且尚未提交的底层计算需要重算。已有成功转写和摘要保留到新分析完整保存后再替换，然后删除断点。需要主动丢弃断点时，通过“更多 → 转写进度 → 从头转写”确认重做。旧版本从未保存的中间结果无法事后恢复。

状态在转写调用前更新，耗时步骤每秒显示已用时间。结果及断点的 `analysis.timings`（结果本身为 `timings`）保存各块 VAD、说话人划分、声纹匹配和 ASR 的毫秒数、处理音频时长、线程数；Debug 开启时也记录不含原文的阶段计时。进度百分比仍为阶段估算，不是剩余时间承诺。真实性能和静音压缩对说话人准确率的影响需真机验证。

Worker 通过独立诊断消息把计时交给主线程的 `RecordingAnalysisRunner`，再由主线程使用 `AppLogger` 读取 Debug 开关并记录。Worker 不依赖 `AppStorage`、`DebugSettings` 或 UI 日志器；日志失败不会使已保存的转写失败，也不会改变进度显示。

原来的 **60 分钟是代码中的产品保护设置，不是录音 API 的硬限制**。当前放宽为单条 **12 小时、文件小于 2 GiB**。手机录音使用 16 kHz、单声道 PCM16，每小时约 115.2 MB，12 小时约 1.38 GB。仍保留时长/大小保护，避免存储耗尽及超大文件处理；不宣称无限录音。高采样率或多声道导入文件可能先达到文件大小限制。

支持 RIFF/WAVE 的 PCM 8/16/24/32 位或 Float32、单/双声道、8–192 kHz；压缩 WAV、扩展格式和 RF64 需先转换。Worker 每次只读取约五分钟音频（另加边界上下文），下混并重采样到 16 kHz，再分至最长 20 秒做 SenseVoice 转写。跨窗口用可用声纹尝试关联说话人，0.65 余弦阈值为启发式设置，不保证复杂/短促/重叠声音的人员一致性。UI 的人声分布概览合并为有限数量显示区间，原始精确时间段仍完整保存。

录音启动时申请系统 `audioRecording` 长时任务，按 Home / 切换其他应用时保持录音；麦克风录音按后台、锁屏持续采集设计。系统音与混合模式的锁屏行为还受 AVScreenCapture、被采集应用和系统状态约束，未完成实机验证。来电、系统取消后台任务、存储不足和达到保护上限时结束并保存。返回录音页面上一级前提示结束；页面销毁时停止。划掉后台、强制停止或进程被杀后不能继续采集。每五秒更新 WAV 头并 fsync，进程意外结束后的草稿会按实际 PCM 长度恢复，但强制停止/断电不保证最后缓存落盘。后台任务与原有 Agent 数据传输通过同一协调器管理，前台清理 Agent 任务不会取消麦克风任务。真实长时稳定性、耗电和锁屏录音仍需设备验收。

## 边录边转写

手机现场录音默认开启“边录边转写”，可以在录音首页或“录音与转写设置”中关闭。需要先准备已有的离线语音模型；模型未就绪时仍允许录音，但明确提示本次仅录音。环境音、混合声音和系统音共用同一份录音 WAV，转写不另存一份音频。

`RecordingLiveWorker` 在独立线程复用 Silero VAD 与 SenseVoice。按停顿结束的语音段识别，连续讲话约每 15 秒分段，不是逐字预览字幕。最多使用两个推理线程，避免挤占采集；协调器始终仅有一个请求在处理，每次最多读取四秒已写入的 PCM。识别慢时允许暂时滞后，不堆积 PCM 消息，也不让模型阻塞麦克风写文件。

停止后先关闭采集并保存 WAV，再处理剩余尾部和最后一句，随后按“转写后生成摘要”和摘要来源设置生成摘要。正常完成不再重新转写整条录音。界面展示最近的转写段落；完整文字保存在该录音记录中。实时转写目前不区分说话人、不提取声纹，需要这些能力时可在详情“更多”中重新完整分析。

已识别文字按小批次追加至 `live-transcript.jsonl`，只有包含新文字或结束时才刷盘；不会反复重写全部历史文字。正常完成后原子保存结果再清理临时日志。进程中断可恢复已完整写入的段落，忽略末尾未写完的一行；未结束的语句可能需要重新识别。实时线程异常、取消或超时保留录音和已有文字，未完成状态不冒充完整转写，也不自动生成完整摘要。后台录音仍使用原有 `audioRecording` 长时任务，不增加权限；后台推理持续性、时延、识别准确性和耗电仍需真机验证。

参考：[Sherpa SenseVoice + VAD 话筒识别](https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html)。

## 仅删除音频

录音详情“更多 → 仅删除音频文件”经过确认后，只删除该条记录在 App 内的 WAV 与相关转写缓存，保留名称、文字、摘要及已生成的声纹。播放器和重新转写入口会识别音频不存在；摘要仍可基于保留文字重新生成。已有但尚未完成的离线分析断点须先完成，避免丢掉尚未合并到正式结果的文字。

音频删除状态先保存，再删除文件，避免进程中断后把保留记录误当成损坏；保存失败不会删除音频。重复手表同步跳过已明确删除音频的同一条记录，不重新下载。手表和导入来源的原始文件不受影响。“删除整条记录”仍删除该条记录的音频、转写、摘要和缓存。

## 声音来源

录音首页的“声音来源”可选 **环境音**、**环境音 + 系统声音**、**仅系统声音**，默认环境音，选择保存在本机；录制期间不可切换。已录文件的来源显示在列表中，旧手机录音按环境音兼容。

- 环境音沿用 AudioCapturer 麦克风采集；环境音和混合模式需要麦克风授权。
- 系统音和混合模式通过原生 AVScreenCapture 的系统授权流程启动，系统可能显示“使用屏幕”等授权文案。视频尺寸设为零，只接收音频 PCM，不采集或保存屏幕画面；页面说明这一授权用途。仅系统模式明确关闭麦克风，不申请麦克风权限；环境音不调用该接口，也不请求屏幕授权。
- 两路 16 kHz、单声道 PCM16 映射到同一采样轴，混合时各以一半增益相加，避免简单拼接导致时长翻倍。原生单调时钟记录采集时长与每帧到达时间，播放暂停和无声期间补静音，保留 500 ms 对齐窗口。单路时间戳重置或时基不一致时只重对齐该路，晚到帧保留尚未写出的部分，Debug 日志记录重对齐次数和超出窗口的样本数，不再因为普通回调延迟或超过四秒的静音结束整段录音。每轮写出至多两秒音频，停止时异步排空尾部。原生队列和实际 PCM 混音缓存仍有上限，真正积压、数据格式异常时停止并保存已录内容。
- 三种模式都复用 WAV 保存、草稿恢复、离线转写和摘要流程；没有增加第二份常驻原始音频。系统取消、其他录制抢占、通话中断、受保护内容或混合模式麦克风不可用时停止，已录内容保留。锁屏/后台的持续性、设备支持的采样格式和时间戳同步仍需实机验证。

系统音不等于所有 App 的声音都可读取。受保护内容、通话和不允许内录的音频可能无法采集；不绕过系统授权或内容保护。复用当前麦克风及后台录音权限，没有添加通话录音等受限权限。内录的授权提示由系统显示。

原生实现位于 `entry/src/main/cpp/recording/RecordingScreenCapture.cpp`，通过 `libentry.so` 增加独立录制接口，不改变模型推理接口。源码更新后需要重新编译并安装包含新原生库的 App。

参考：[华为 AVScreenCapture 录音实践](https://developer.huawei.com/consumer/en/doc/best-practices/bpta-audio-record-base-on-avscreencapture)、[OpenHarmony 音频回调及纳秒时间戳](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-media-kit/capi-native-avscreen-capture-base-h.md)。

## 手表接收

首页“手表录音”或底部手表入口查询运动健康中已配对的手表，使用与 `D:/MobiAgent/clawmate-watch` 一致的 Wear Engine v1 协议。先注册消息和文件接收器，再启动手表应用握手；分页获取录音、整文件接收、校验大小与 SHA-256，落盘后确认，手表原文件保留。

接收成功导入 `recording-analysis/<UUID>/audio.wav`，记录 `sourceId + recordingId + sha256`。重复同步核对手机自己的正式副本并复用，保留已有名称、转写与摘要；发现副本损坏时重新接收并恢复音频。已导入后清理接收缓存，避免常态保留两份音频；缓存清理失败不把已保存录音判为失败。默认接收后顺序转写尚未分析的录音，并根据摘要设置继续整理，开关可关闭；模型未准备时先保留文件。

合入后的手机和手表共用包名 `com.coevomind.clawmate` 与手机现有 AGC APP ID `6917613102135452205`，独立手表工程的旧 APP ID 不用于当前版本。签名和分别调试步骤见[多端集成说明](WATCH_INTEGRATION.md)。手机必须在华为开发者平台开通 Wear Engine，运动健康保持配对连接及授权。SDK 的服务未开通、账号未登录和设备断开错误会显示对应提示；代码无法代替服务审批。当前接收与分析在录音页面前台执行，退后台可停止任务，已保存录音保留，重连可补传。手表按五分钟保存片段，单次监听六小时的保护设置沿用手表项目。

手机通过本地 HAR 依赖 `@clawmate/watch-bridge` 使用 `phonebridge` 中的唯一接收库，旧路径 `utils/recording/WatchRecordingClient.ets` 保留兼容导出。手表入口和手机接收端的同步检查位于 `tests/watch`。手机使用现有 `client_id` 元数据，没有改动签名信息。

## 自定义模型下载地址

在“离线语音模型 → 更多选项”中填写目录地址，点击“保存地址”或直接点击“下载模型”（会同时保存）。地址保存在本机，重新进入页面或重启 App 后继续使用；“恢复默认”会恢复并保存 ModelScope 镜像地址。模型页默认只展示准备状态、下载大小和主要操作，文件导入也在“更多选项”中；文件名和校验实现细节不再常驻展示。

下载显示线性进度条、百分比与总准备大小。整体进度按五个固定校验模型的字节数加权，复用已验证文件；即使下载接口未提供总长度，也可依据固定文件大小更新，不从文案解析进度。全部文件完成校验后才显示 100%；失败或取消不显示完成，重试会重新计算本轮进度。

默认地址：

```text
https://modelscope.cn/models/fengerhu1/recording-analysis-models/resolve/master
```

也可以直接粘贴 ModelScope 仓库页面链接 `https://modelscope.cn/models/fengerhu1/recording-analysis-models`，App 会自动补齐 `/resolve/master`。使用其他 HTTP/HTTPS 文件服务器时，填写同时存放下表五个文件的目录，末尾不必加斜杠。例如 `http://192.168.1.2:9123/recording-models`。下载时分别拼接 `sensevoice.int8.onnx`、`tokens.txt`、`silero_vad.onnx`、`segmentation.int8.onnx`、`speaker.onnx`。

输入应为不带账号密码、查询参数或页面锚点的目录 URL，无需填写 ModelScope 令牌。更换地址只改变文件来源，仍须通过当前版本固定的 SHA-256 校验，不接受任意替代模型。已校验的模型可复用，失败会显示具体模型名称及错误码。

下载请求会发送 `ClawMate/1.0 (HarmonyOS; recording models)` 客户端标识。ModelScope 会对空白或默认下载客户端标识返回 HTTP 403（UA ACL）；系统旧下载接口可能将该响应归并成“下载失败（8）”。这个错误码本身不足以判断网络断开，应以下载服务日志为准。

## 实现

- `RecordingPage.ets`：独立页面、列表、录制、分析、回放、声纹比较及模型管理。
- `RecordingStore.ets`：`filesDir/recording-analysis/<UUID>/audio.wav` 与 `record.json`；元数据临时文件写入后原子替换。
- `RecordingModels.ets`：`filesDir/recording-models/` 下的模型下载/导入及 SHA-256 校验；`download-source.json` 保存下载目录设置，默认从 ModelScope 获取五个固定版本文件。
- `RecordingAnalysisWorker.ets`：默认 VAD → 最长20秒的 SenseVoice 转写；用户开启区分后增加 Pyannote + 3D-Speaker 分段、代表声纹提取和跨块匹配。分段未覆盖的人声保留为“未区分”；重叠时间保留，不保证把混叠声音还原成独立音轨。
- `RecordingAnalysisCheckpoint.ets`：完成前缀与有界当前块分开原子提交，两种转写模式使用独立断点；`RecordingSpeechTimeline.ets` 负责静音压缩及原始时间映射；`RecordingPerformance.ets` / `recording/RecordingCpu.cpp` 提供上限四线程的 CPU 分配策略。
- `RecordingInbox.ets`：只接收 WAV Want，及时复制临时授权 URI；保留原画像分享处理分支。
- `sherpa_onnx` 固定为 `1.13.3`，随模块依赖及锁文件解析。CPU 推理，未假设本机麒麟 NPU 可直接加速 ONNX。

文件存储体积不等于运行内存。长录音的分段、模型与中间张量会占额外内存；耗时、功耗、多语种准确率、多人同时发言效果需真机验证。说话人名称是用户编辑标签，未使用真实联系人或自动建立跨录音的人员数据库。

### 原生运行库共存

MNN 使用静态 C++ 运行库时，必须将 `libc++_static.a`、`libc++abi.a`、`libunwind.a` 的符号留在引擎内部，避免与 sherpa/ONNX Runtime 使用的共享 C++ 运行库互相覆盖。App 自身的 `libentry.so` 同样隐藏这些归档符号。已知表现是几秒录音在人声检测开头长时间不动，原生采样进入 `locale::use_facet`、C++ 抛异常和 `libentry.so` 的回溯函数。

App 侧链接修正在 `entry/src/main/cpp/CMakeLists.txt`；远端 MobiInfer 仓库的对应修复记录在 `patches/recording-native-runtime-visibility.patch`。两处均需重新编译对应原生库并重新安装 App 后才生效，下载模型不会更新这些库。模型初始化和检测进度已拆开显示，检测阶段显示已处理秒数。

静态 ELF 检查（仅检查已有库，不触发构建）：

```powershell
python scripts/check_recording_native_runtime.py --nm <SDK的llvm-nm.exe路径> --entry <本次libentry.so路径> --mnn entry/libs/arm64-v8a/libMNN.so
```

重链接前可通过 `--write-baseline <JSON路径>` 保存 MNN 公共 API 符号，重链接后通过 `--baseline <JSON路径>` 检查 API 是否保留。旧库会被检查器判为失败；只有新库的导出检查和真机录音分析都通过，才算修复验证完成。
