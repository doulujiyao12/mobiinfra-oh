# Codex 电脑会话共享与接力

## 1.1.7：跟随原桌面后台

**1.1.8 格式修复：** 公开 App Server 可省略普通文本的 `text_elements`，但桌面协调通道会先把原始输入存入内存，而官方消息解析函数直接读取该数组长度。1.1.7 使用公开协议的精简文本对象，实际手机下发后可能触发桌面渲染错误。现在只在协调边界补齐 `text_elements: []`，合并相邻文本并以空行分隔，不改变独立 App Server 路径。已用实际安装的官方纯解析函数复现遗漏字段的 TypeError，并确认规范化输入通过；真实持久历史通过原生只读接口返回完整数组，重启桌面后应可恢复。此前只读订阅与模拟测试没有覆盖此契约，现已加入回归测试。官方程序和历史文件均未修改。

手机从“电脑会话”选择已经在官方桌面打开的本地项目会话。ClawMate 先检查历史元数据与已授权项目，再通过本机协调 IPC 查询持有者并订阅快照；手机与电脑共用原 ID 和执行后台。只有手机提交消息才发起执行，读取和订阅不调用模型。

- `desktop-ipc.mjs`：Windows 使用 `\\.\pipe\codex-ipc`；Unix 使用同一 `CODEX_HOME` 下的 `ipc/ipc.sock`，验证所有者和权限。长度前缀 JSON 帧，声明真实 `clawmate` 身份，不冒充桌面或 IDE，不接管所有权。仅转发选定方法，不开放通用 RPC。
- `desktop-sessions.mjs`：发现原持有者后，原地转发消息、命令/文件审批、补充回答和精确轮次停止；接收版本化快照与 Immer 增量，投影为既有手机任务结构。电脑自行发起的轮次也会同步。桌面正在执行时手机可停止，完成后再发送，不开启第二个写入进程。
- 仅支持已授权确切项目目录、`local` 主机、非子会话。正文只投影用户/助手、计划、命令、diff，不透传推理、OAuth 或未知对象。暂不支持的确认项保留在电脑端，手机显示处理提示。
- 手机每轮显式选择审批与沙箱，`permissions:null` 防止继承桌面的完全访问配置；最终权限仍经过桌面自身运行目录与组织策略计算。电脑自行发起的执行遵循电脑设置，不由手机覆盖。
- 同一时刻最多观察 20 个会话；只淘汰空闲观察，绝不终止任务。连接关闭仅取消订阅。桥接重启、持有者退出、版本改变、目录变化、增量缺失时阻止控制并显示等待同步，不能宣称桌面任务已停止。缺失快照仅重试只读订阅；操作不自动重试。
- 请求编号防重复执行；结果未知时保留手机草稿，只有匹配的桌面确认才清空。审批编号绑定持有者和请求内容，已处理或正提交的审批不可重复提交。停止携带已同步轮次 ID，避免误停下一轮。
- 文件回传继续只收集新完成轮次最终答复中的受控项目成品，不批量补抓已完成历史，不扫描过程文件。

适配依据是本机安装的 Windows Codex **26.1013.4894.0**、内置升级运行时 **0.163.0-alpha.10.2** 的实际协议；共享快照版本固定为 **11**，转发方法分别固定版本。这是官方客户端的内部协调接口，**不是公开稳定 API**，未来升级不兼容时需要维护适配。未修改官方安装文件或缓存，未读取/复制 OpenAI 登录凭据。

本次只读真机验证确认了 initialize、持有者发现、订阅和 canonical 历史投影；没有向真实用户会话发消息、审批或停止，也没有调用模型。模拟回归覆盖转发参数、双端轮次、增量缺失、断线、权限、重复提交、审批竞态、成品与关闭行为。Mac/Linux 仅实现同协议 Unix 通道，尚未实机验证。桌面 UI 的真实执行联调仍需重编译后人工验证。

ClawMate 电脑端产品默认启用；手动桥接配置加入 `"desktopCoordination": true`。`/v1/info.desktopSessionSharingSupported` 是能力开关，单会话的实际状态见 `executionTransport` / `desktopConnected` / `executionSource`。

手机新建的独立会话仍使用原 App Server；旧副本不会自动合并。没有在线持有者时，保留下述原生锁接力路径；协议异常不会悄悄绕开原持有者启动第二个执行后台。

## 1.1.10：Linux 原生 App Server daemon

Linux CLI 的原生 managed daemon 不一定在桌面私有 IPC 上注册会话持有者，因此不能仅靠 Windows 的 follower 协议共享。现在会在桌面协调通道没有持有者时，寻找同一 UID、网络命名空间和 `CODEX_HOME` 的 Codex Unix 监听 socket，检查监听进程、socket/父目录私有权限；只连接其实际 socket 路径，不开放新的 Codex 网络监听器。

通过公开 App Server 的 WebSocket 协议初始化，先用 `thread/loaded/list` 判断原 ID 是否已加载；唯一持有者才可接入。`thread/resume(excludeTurns:true)` 建立订阅，不传模型、目录或权限覆盖。最近两轮通过 `thread/turns/list` 恢复有界显示，随后合并实时事件和后台重放的待处理请求。手机发送走同一后台的 `turn/start`，显式携带手机选择的文件范围及审批方式，并等待实际 `turn/started` 确认，防止停止命中尚未启动的编号。已知正在执行的轮次不追加第二条手机任务；极短的跨客户端竞争仍由原生 App Server 仲裁。

命令/文件审批与补充问题复用现有手机接口，后台的 `serverRequest/resolved` 使其他端按钮失效。未知 MCP、登录等交互不返回拒绝，留给原电脑客户端处理；不把其敏感内容发到手机。断线标记为状态未知，清空旧审批，不重发任务；重新打开会话后恢复订阅。停止携带确切轮次号；关闭桥接只关闭自身 socket，不终止、升级官方后台，不删除写锁。最终答复的受控文件回传复用现有实现。

服务器真实 **0.163.0** 隔离测试使用独立 `CODEX_HOME`、临时项目和本地模拟 Responses 服务，验证自动发现、原 ID 双向消息、显式沙箱、重复请求、双端审批及重放/失效、停止、运行中断线重连、原进程存活，以及最终 PDF 的受控交付。未向用户真实会话提交任务或执行审批。Windows 的桌面 follower 与独占 stdio 接力回归保留。原生独占 CLI（如 `--no-daemon`）、其他用户、不同 `CODEX_HOME`、任意 TCP 后台仍需释放后接力。

协议依据：[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)，并对照服务器 **0.163.0** 导出的实际 Schema。手机沿用 `executionTransport=desktop` 的既有实时共享状态，新增 `executionBackend=daemon` 仅用于诊断，无需重编译手机包。

## 1.1.4–1.1.6 及无在线持有者时：原 session 接力

电脑端 **1.1.4** 起，手机选择电脑会话后直接在同一 session 中继续。1.1.2/1.1.3 创建的独立副本保持原样，不合并或覆盖；接力原会话时需从“电脑会话”重新选择原条目。

### 使用方式

手机 Codex 左上角菜单 → 电脑会话 → 选择原会话 → 发送消息。1.1.5 起，未接入的电脑会话默认“允许工作目录内修改 + 请求批准”，不继承电脑端的高权限。空闲时可修改文件范围及“请求批准 / 帮我批准 / 完全访问控制”，下一条消息生效。现有条目保留已有选择。

如果提示电脑仍持有会话，本轮没有下发。原客户端即使空闲也可能保留写锁，仅停止生成或切换标签不一定释放。必要时完全退出原 Codex 客户端，保持 ClawMate 桥接服务运行，再手机重试。桥接不会杀死电脑客户端、强行解锁或操作用户的原会话文件。手机本轮完成、失败或停止后，执行进程退出并释放会话；电脑可重新加载原会话继续。

这实现了**接力与历史统一**，不保证官方 Codex 已打开窗口实时刷新。桥接没有接入其私有后台或修改其缓存。需使用支持同等原生写锁机制的电脑客户端；本次验证针对内置 Codex **0.160.1**。

### 实现与边界

- `thread/list` 分页查询已授权项目的确切目录，返回前再次核对真实路径、来源、父会话和临时标记。接力过的原会话仍显示在电脑列表。
- `thread/read(includeTurns:false)` 校验元数据，`thread/items/list` 分页取显示记录；旧格式回退 `thread/turns/list(itemsView:full)`。读完后重新检查授权，图片历史只显示附件提示，不读取历史中的任意文件路径。
- `/v1/threads/<id>/resume` 只登记原 ID 和手机权限，不执行、不创建新线程。重复登记返回同一条目，不允许悄悄扩大权限。旧副本接口只用于兼容老客户端。
- 每次 `turn/start` 创建独立 stdio App Server，以原 ID 执行 `thread/resume(excludeTurns:true)`；验证返回 ID、目录、来源、审批及已知沙箱类型后再下发。0.160.1 的 resume 可能回显旧沙箱，真正的文件范围和审核者在每次 `turn/start` 中显式覆盖；真实运行中已核对切换结果。独占写锁由 Codex 自身提供。`thread/read.status=notLoaded` 仅代表当前后台未加载，不能代替跨进程互斥。
- 每轮重新恢复，加载电脑中途写入的最新上下文；不会复用上一轮的内存缓存。正文展示量有上限，模型上下文由 Codex 完整恢复。
- 审批与停止路由到持有原会话的执行进程；成功成品仍写入原 session 的受控交付快照，手机保存到原 ID 对应沙箱。断开手机不终止电脑任务。
- 结束后先进入 `releasing`，等待执行进程退出，随后恢复最终状态。释放期间不能启动下一轮。释放失败保留占用状态，可按停止重试；不会误称已交还电脑。
- 相同 turn 请求重试不重复执行。服务重启保留登记、请求编号、文件快照；执行中的任务按中断处理。空闲时手机轮询读取最新持久历史，更新电脑新增记录。

桥接与原客户端必须使用同一 OS 用户、同一 `CODEX_HOME`。Windows、WSL、远端主机、其他用户和云端独有历史不会因账号相同自动合并。工作树、子目录必须分别列入授权项目。排除子智能体、临时及已归档列表项；列表最多 1000 项，正文分页且有限额。老历史成品不会批量补抓，需要继续对话重新交付。

### 原接力路径验证

接口依据 [OpenAI Docs 的 App Server 文档](https://learn.chatgpt.com/docs/app-server)，并核对内置 **0.160.1** Schema。模拟测试覆盖身份与目录权限、重复登记/重启、原生写锁错误、逐轮新进程、释放中禁发、停止/审批/文件回传，以及电脑历史刷新。

真实运行时测试使用隔离 `CODEX_HOME` 和拒绝全部推理的本地假服务，分别验证 paginated/legacy 两种格式：电脑占用时手机被拒绝且未发模型请求；电脑退出后手机写入原 ID；新电脑客户端能恢复手机消息；电脑新增消息后手机再次接力能够看到。测试不读取用户真实会话、不调用真实模型，也未验证官方桌面窗口的实时渲染。
